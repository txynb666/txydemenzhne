# 详细项目设计方案
版本为2026年11月6日课程MVP设计补充，依据现有代码和需求定义，不代表完整院内系统已实现。
## 工程与部署结构
FastAPI app/main.py处理聊天、确认和历史接口；app/api/admin/routes.py处理JWT登录、知识库、提示词、审计及预约分诊审核。static是员工端，templates是管理员服务端页面。数据库为SQLite，app/repositories/schema.py统一初始化；可用Docker部署，src归档保留源码快照，运行主入口仍是app目录。
## Agent与知识库
自研轻量Harness在app/agents/harness.py内执行模型决策、工具调用、结果回填和恢复；默认最多5轮、每次最多1个写工具，支持确认挂起与执行轨迹。未使用LangGraph，不把自研循环冒称第三方框架。知识库在data/kb_files，检索由app/rag进行500字切片、50字重叠、BM25及向量混合Top3。模型走可配置OpenAI兼容服务，云端或本地均可，向量来源和模型变更需重建索引。
## 三处实际人工确认或审核点
H1报销草稿：Harness先签发待确认token，员工在对话卡片确认或取消，确认后才建草稿；一次性凭证防重放。接口POST /chat/confirm，用户演示身份仍是demo_user。
H2预约分诊：AI预约固定pending_triage，AI工具传入任何triage_confirmed_by被拒。后台/admin/triage列待审核预约，管理员填写原因并确认或退回；确认人由服务器JWT取得，写appointment_reviews；退回释放一次名额，重复审核被拒。
H3提示词发布：管理员在/admin/prompts核对规则和文本后手动保存，POST/PUT管理接口鉴权，写版本号、修改人并实时生效。是人工发布审核，不是双人审批。
三处有不同操作入口、状态或版本效果与留痕。H2的管理员是课程演示角色，不等于真实医护资质；真实临床签核角色、身份验证和审批制度仍待补齐。
## 主要数据结构与事务
conversations/messages保存会话；clinic_slots/appointments保存容量、幂等键及待分诊状态；eligibility_tokens绑定报销参数、签名、有效期和使用标记；pending_actions保存确认待办；agent_steps保存执行轨迹；prompt_templates保存提示词版本。新增appointment_reviews以appointment_id唯一约束防止重复审核，包含reviewer、decision、reason及created_at。
预约创建使用容量条件更新；审核使用BEGIN IMMEDIATE后读待审状态，同事务更新预约、退回名额和审核记录。AI不能调用审核函数，审核不加入TOOLS_SPEC；管理员路由单独校验身份。部署多工作进程时仍由SQLite事务及唯一约束保护，但本轮只验证单进程线程并发，未证明大规模性能。
## 接口与交互规格
GET /admin/api/appointments/pending仅管理员可读，最多最近100条；POST /admin/api/appointments/{id}/review只接受confirm/reject和1至500字符的原因。空白原因由服务层拒绝，未知action由422拒绝。未登录code1005、员工越权code1003；已审核code2002。HTTP200不代表业务成功，前端检查code；聊天还必须检查SSE error/done事件。
审核页使用textContent写入用户原文，不通过innerHTML执行原始症状内容；发送前浏览器再次确认，写入中禁止重复点击。错误显示toast并允许重试。知识库上传与模板发布仍按既有权限链路处理。
## 安全 降级与边界
密钥来自.env或环境变量，不提交到仓库；JWT签名、资格校验签名不能用相同演示默认值上线。默认账号只用于本机教学，未建独立临床RBAC、CSRF防护体系及生产安全评估，不直接对公网开放真实健康数据。对外部署前需HTTPS、身份及数据授权、最小权限和审计检查。
模型故障输出明确错误，不以空答当成功；故障测试替换外部模型客户端但HTTP及数据库真实。数据源只读快照、异常人工接手、真实叫号及院内队列仍未完整实现，不能声称本MVP完成全部P0需求。
## 验收与交付
回归命令python scripts/verify.py。本轮39项后端与6项前端通过，5个新增集成场景覆盖正常、边界、对抗、权限和故障；详见Test目录和原始JSON证据。量化需求验收标准与拟业务试点仍沿用系统需求分析方案，不能拿45项离线测试代替医院验收。
