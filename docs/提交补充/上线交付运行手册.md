# 项目上线交付运行手册
## 交付范围和状态
本手册适用于课程演示MVP，不表示完成医院生产上线。源码主入口app/main.py，现有文档在docs，测试说明与过程在Test，归档在src。尚无已验证的公网后端URL，地址清单另见部署网站地址说明。
## 环境与配置
Python 3.11或3.12，Node.js 20以上用于前端测试，或使用Docker Desktop与Compose。先备份数据，再复制.env.example为.env；按供应商设置LLM_API_KEY、LLM_BASE_URL、LLM_MODEL及EMBED三项。不要截图或上传密钥，修改JWT_SECRET和ELIGIBILITY_SECRET。使用本地Ollama时参考.env.ollama.example；Docker访问Windows主机用host.docker.internal，直接Python运行改localhost。实际需先安装并下载对话及向量模型。
## 首次运行
在项目根目录执行python -m pip install -r requirements.txt，然后python -m uvicorn app.main:app --host 127.0.0.1 --port 8000。打开http://localhost:8000；后台http://localhost:8000/admin/login。若用8001启动，浏览器同步改为8001。本机现有预览采用8001，localhost仅当前电脑可访问，不是公网部署。
Docker方式先确认clinic.db是文件而非目录并备份，再docker compose up -d --build。数据持久化在clinic.db、data/kb_files和data/index。不要把.env、运行数据库或患者资料加入Git。
## 三个人工点操作
H1员工端触发报销草稿预览后核对金额、发票与制度，确认才建草稿，取消不落库；H2管理员打开/admin/triage，逐条核实并填写审核原因后确认或退回；H3管理员打开/admin/prompts，审核内容后保存并记录版本，必要时回滚。admin/admin123和employee/emp123是演示账号，真实部署先改密码及权限。
## 上线前检查
执行python scripts/verify.py，查看artifacts/verification；模型自检python scripts/check_models.py会发出真实对话与向量请求，云配置可能产生费用，模型费用及余额需自行核实。健康接口/health返回ok只证明进程可响应，不证明LLM、HIS、临床或财务系统正常。冻结版本、依赖、备份、负责人和回退窗口，验证TLS及访问控制后再开放。
## 日常运行与排障
Docker查看docker compose ps及docker compose logs --tail 100；端口被占用先核对现有进程和端口再改配置。模型402检查余额，401检查密钥与供应商，向量失败检查模型名、地址及维度；修改向量模型后从后台重建索引。SSE HTTP200且error事件仍为失败，保存日志但脱敏令牌和密钥。
## 备份与回退
SQLite一致性备份优先使用Python sqlite3.Connection.backup到新文件，先在测试副本验证可读取；制度原件及版本、必要配置另做授权备份。恢复前停写、备份当前状态、恢复数据库和匹配的制度版本，重建向量索引，核对记录数量及三个人工点，失败则回退。Git回退代码不会自动回退数据库；本轮新增表采用幂等建表，不删除原表。
## 运维与交接验收
交付版本、运行命令、非敏感配置模板、测试结果、账号移交和恢复演练记录由接收人确认。异常问题登记业务号、时间、版本、影响、负责人和处理状态；没有实际演练证据时写NOT_RUN。真实运维值班、可用性SLA、留存期限和成本需另行约定，不将教学报价视为全年服务合同。
